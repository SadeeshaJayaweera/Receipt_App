# Pull Request 33: Health Checks & Observability

## Title
`feat(observability): production health check probes with readiness, liveness, and memory telemetry`

## Overview
This PR implements enterprise health check probes and system telemetry (`backend/src/routes/healthRoutes.js`) supporting modern container orchestrators (Kubernetes, Docker, Cloud Run, AWS ECS). It decouples liveness checks from deep database readiness verifications, preventing cascading orchestrator restarts during momentary database load while ensuring unready pods are not routed user traffic.

## Key Changes
1. **System Health & Observability Metrics (`GET /api/health`)**:
   - Preserves backward compatibility returning `status: "OK"` and `mongodb` connection status.
   - Enriches response with `uptimeSeconds`, system `timestamp`, runtime `environment`, and detailed process memory telemetry (`rss`, `heapTotal`, `heapUsed`).
2. **Container Liveness Probe (`GET /api/health/live`)**:
   - Lightweight, non-blocking check verifying the Express event loop and process are alive and responsive.
   - Returns HTTP 200 `{ status: "alive", uptimeSeconds, timestamp }`.
3. **Database Readiness Probe (`GET /api/health/ready`)**:
   - Checks MongoDB connection state (`mongoose.connection.readyState === 1`).
   - When connected: executes an active `admin.ping()` to verify read/write database responsiveness and returns HTTP 200 `{ status: "ready", database: "connected", dbLatencyMs, timestamp }`.
   - When disconnected: fails fast with HTTP 503 Service Unavailable `{ status: "unready", database: "disconnected", message: "..." }`, instructing load balancers to halt traffic routing.
