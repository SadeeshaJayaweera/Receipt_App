# Pull Request 35: End-to-End Automated Browser Tests

## Title
`test(e2e): end-to-end automated browser tests for critical business journeys`

## Overview
This PR implements comprehensive automated end-to-end (E2E) browser journey tests (`frontend/src/tests/e2eUserJourneys.test.jsx`) covering the critical user journeys required for daily operations of the juice receipt management platform. It validates seamless user interaction across authentication, catalogue management, POS cart assembly, financial change calculation, dual-format receipt preview, ESC/POS thermal printing, and void auditing.

## Key Changes
1. **Authentication Accessibility Polish (`frontend/src/pages/Auth/Login.jsx`)**:
   - Added explicit `htmlFor` and `id` bindings for Email (`#login-email`) and Password (`#login-password`) input fields, ensuring full screen reader and assistive technology conformance.

2. **End-to-End User Journeys Suite (`frontend/src/tests/e2eUserJourneys.test.jsx`)**:
   - **Journey 1: User Authentication & Session Initialization**:
     - Tests credential submission (`admin@juicepos.com`), token acquisition, and route transition to `/dashboard`.
     - Validates friendly error alerts when authentication fails.
   - **Journey 2: Product Catalogue Management Flow**:
     - Validates instant search filtering by flavour name, SKU, and description.
     - Tests interactive stock availability toggle (`isAvailable` state).
     - Tests "Add Flavour" modal dialog submission with SKU (`DRA-03`) and pricing (`Rs. 750.00`).
   - **Journey 3: POS Receipt Checkout & Financial Calculation Flow**:
     - Tests fast-touch menu tile selection into the POS order ticket.
     - Validates live subtotal, discount, and tax calculation via `calcEngine.js`.
     - Tests cash tender input and real-time change calculation (`Rs. 650.00` change on `Rs. 2000.00` tender).
     - Submits checkout and verifies the success dialog with sequential receipt number (`CITRUS-202611-0001`).
   - **Journey 4 & 5: Dual-Format Receipt Preview & Printing Triggers**:
     - Tests default 80mm continuous thermal roll layout.
     - Tests seamless toggle to A4 standard invoice document view.
     - Verifies prominent `VOID` watermark and audit justification for voided sales.
     - Verifies execution of `printThermalReceipt` and `downloadReceiptPdf` actions.
   - **Journey 6: Receipt History, Advanced Search & Void Audit Workflow**:
     - Tests query search by receipt number (`CITRUS-202611`) and customer details.
     - Tests status filtering chips.
     - Exercises receipt voiding modal, enforcing mandatory justification entry before submitting.
