# Pull Request 15: Receipt Lifecycle Management & Financial Immutability

## Title
`feat(receipts): receipt lifecycle states (draft, issued, voided), immutability guarantees, and void audit logging`

## Overview
This PR implements strict financial lifecycle management for business receipts. It introduces distinct receipt states (`draft`, `issued`, `voided`), enforces that finalized/issued receipts are immutable against silent item/price modifications, implements compliant receipt voiding with mandatory audit reasons, and tracks all status transitions in an append-only audit log.

## Key Changes
1. **Lifecycle States & Audit Schema (`backend/src/models/Receipt.js`)**:
   - Supported statuses: `draft`, `issued`, `voided` (default `issued`).
   - Added `voidedAt` (Date), `voidReason` (String), and `voidedBy` (ObjectId reference to User).
   - Added `statusHistory` array tracking every state transition (`fromStatus`, `toStatus`, `changedAt`, `reason`, `changedBy`).

2. **Receipt Financial Immutability & Lifecycle Service (`backend/src/services/receiptService.js`)**:
   - `voidReceipt(userId, receiptId, reason)`:
     - Requires a valid reason of at least 5 characters.
     - Transitions status to `voided`, records timestamp, operator, and appends to audit history.
     - Rejects voiding an already voided receipt.
   - `issueDraft(userId, receiptId)`:
     - Transitions draft receipts to finalized `issued` state.
   - Immutability Enforcement on `update()`:
     - Rejects any edits to `voided` receipts.
     - Rejects changes to items, pricing, discounts, taxes, or currencies on `issued` receipts.
   - Audit Protection on `delete()`:
     - Prevents deletion of `issued` receipts for accounting compliance (requires voiding instead).

3. **Routes and Controller (`backend/src/routes/receiptRoutes.js` & `receiptController.js`)**:
   - Added `POST /api/receipts/:id/void` with payload validation.
   - Added `POST /api/receipts/:id/issue`.

4. **Validation Schemas (`backend/src/validators/receiptValidators.js`)**:
   - Added `voidReceiptSchema` requiring `reason` (5–300 characters).
