## PR-01: Baseline Engineering Audit and Architecture Inventory

### Objective
Establish a comprehensive baseline audit of the existing Juice Receipt App codebase, documenting system architecture, feature inventory, technical debt, security risks, database limitations, financial calculation flaws, and initial test/build execution results prior to executing structural refactoring.

### Existing problem
The repository lacked formal architecture documentation, an engineering health assessment, and an audit of critical bugs. Critical flaws existed uncatalogued—including cleartext password logging, insecure CORS wildcard fallback, unverified financial totals, race conditions in receipt numbering, missing multi-currency persistence, and absence of backend automated tests.

### Implementation
1. Inspected all frontend and backend source files, dependencies, database schemas, and documentation.
2. Verified initial build and test behavior, uncovering failing commands and uninstalled packages.
3. Created `docs/engineering/INITIAL_AUDIT.md` providing an in-depth breakdown of system architecture (with Mermaid diagram), feature inventory, critical risks across security, financial integrity, architecture, and UI/UX.
4. Established the documentation structure (`docs/engineering`, `docs/pull_requests`, `docs/architecture`, `docs/security`, `docs/testing`, `docs/deployment`).

### Files changed
- `docs/engineering/INITIAL_AUDIT.md`: Created detailed baseline audit report.
- `docs/pull_requests/PR-01.md`: Created formal PR record for PR-01.

### Architecture impact
No production code modified. Established documentation baseline and project roadmap for the 40 PR transformation.

### Testing
- Executed `npm test` on backend: Confirmed failure due to missing test script.
- Executed `npm test` on frontend: Documented missing dependency state.
- Checked node and npm compatibility (Node v20.20.0, npm 10.8.2).

### Security considerations
This audit directly identified severe security flaws (plaintext credential logging in `routes/auth.js`, insecure CORS in `server.js`, and unvalidated inputs) which will be systematically remediated in subsequent PRs.
