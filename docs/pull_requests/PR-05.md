## PR-05: API Validation and Standardized Error Handling

### Objective
Introduce strict schema validation for all incoming API requests using Zod, attach unique request correlation identifiers (`X-Request-Id`), and establish a centralized, sanitized error-handling pipeline that prevents leaking sensitive server internals or database errors.

### Existing problem
- The application previously accepted arbitrary JSON payloads without runtime validation, making the API vulnerable to missing fields, type mismatches, NoSQL parameter injections, and malformed data.
- Error handling was inconsistent across endpoints; uncaught errors could leak stack traces and raw database error strings to clients.
- Requests lacked traceability or correlation IDs for backend debugging.

### Implementation
1. **Request Correlation Identifier (`backend/src/middleware/requestId.js`):**
   - Injected UUID-based `X-Request-Id` header into every request and response (`req.id`).
   - Integrated request ID into all server console logs.
2. **Generic Zod Validation Middleware (`backend/src/middleware/validate.js`):**
   - Validates `req.body`, `req.query`, or `req.params` against Zod schemas.
   - Formats failed validations into structured, field-level arrays of `{ field, message, code }`.
3. **Endpoint Validation Schemas (`backend/src/validators/`):**
   - `authValidators.js`: Validates `registerSchema` (businessName, email format, password min 6 chars), `loginSchema`, and `updateProfileSchema`.
   - `flavourValidators.js`: Validates `createFlavourSchema` (positive price, required name) and `updateFlavourSchema`.
   - `receiptValidators.js`: Validates `createReceiptSchema` (requires non-empty `items` array, positive totals, valid paymentMethod enum) and `updateReceiptSchema`.
4. **Standardized Central Error Handler (`backend/src/middleware/errorHandler.js`):**
   - Uniform error envelope: `{ status, requestId, message, details, timestamp }`.
   - Maps Mongoose `CastError`, `ValidationError`, and duplicate key errors (`code: 11000`) to readable 400/409 responses.
   - Sanitizes 500 responses in production to prevent leaking internal stack traces.
5. **Comprehensive Automated Tests (`backend/tests/validation.test.js`):**
   - Validates `X-Request-Id` header generation.
   - Tests registration rejection on malformed emails and short passwords.
   - Tests login rejection on missing credentials.
   - Tests flavour rejection on negative prices.
   - Tests receipt rejection on empty item lists.

### Architecture impact
Introduced a declarative validation boundary at the HTTP entry point. Controllers and services now receive guaranteed type-safe, trimmed, and sanitized data structures.
