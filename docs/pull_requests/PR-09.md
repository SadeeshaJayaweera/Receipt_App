# Pull Request 09: Schema Optimization, Indexing & Model Validation

## Title
`feat(db): optimize MongoDB schemas, validation, and multi-tenant compound indexes`

## Overview
This PR hardens the MongoDB data models (`User`, `Flavour`, `Receipt`) with enterprise-grade data validation, defaults, field constraints, and compound indexes tailored for high-volume, isolated multi-tenant operations.

## Key Changes
1. **User Model Hardening (`backend/src/models/User.js`)**:
   - Added email format regex validation and automatic lowercase transformation.
   - Enforced business name length bounds (2–100 characters).
   - Added user preference fields: `defaultCurrency` (`LKR` or `USD`), `taxEnabled` (default `false`), `taxRate` (0–100%), and customizable `receiptFooter`.
   - Maintained unique index on `email`.

2. **Flavour Model Optimization (`backend/src/models/Flavour.js`)**:
   - Added field constraints on `name` (1–80 chars, trimmed) and `price` (minimum 0).
   - Added compound index `{ userId: 1, name: 1 }` with `unique: true` preventing duplicate flavour names per tenant.
   - Added compound index `{ userId: 1, isActive: 1 }` for fast active product lookups.
   - Added automatic Mongoose timestamps (`createdAt`, `updatedAt`).

3. **Receipt Model Optimization (`backend/src/models/Receipt.js`)**:
   - Added currency field restricted to `LKR` and `USD` (defaults to `LKR`).
   - Added receipt lifecycle status (`draft`, `issued`, `voided`, defaulting to `issued`).
   - Added explicit financial breakdown fields: `subtotal`, `discount`, `taxRate`, `taxAmount`, and `totalAmount`.
   - Added customer contact metadata: `customerPhone` and `customerEmail`.
   - Strict line item validation ensuring `quantity` is a positive integer, `price` is non-negative, and `subtotal` is non-negative.
   - Added high-performance compound indexes:
     - `{ userId: 1, createdAt: -1 }` (reverse chronologically sorted receipt history).
     - `{ userId: 1, receiptNumber: 1 }` with `unique: true` (tenant collision-safe receipt lookup).
     - `{ userId: 1, currency: 1, status: 1 }` (financial aggregation by currency and status).

4. **Validator & Service Synchronization**:
   - Updated `receiptValidators.js` to accept and validate the new fields with strict payload rejection on unauthorized fields.
   - Updated `receiptService.js` to map and persist `currency`, `status`, `subtotal`, `discount`, `taxRate`, `taxAmount`, `customerPhone`, and `customerEmail`.
   - Updated `server.js` to prevent double-listening on test execution and cleanly handle test environments.
