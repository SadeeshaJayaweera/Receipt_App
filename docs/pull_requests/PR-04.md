## PR-04: Backend Architecture and Service Organization

### Objective
Restructure the backend into modular, layered architectural components with explicit separation of concerns between HTTP routes, controllers, business services, domain models, custom error classes, and middleware. Fix Linux filesystem case-sensitivity defects.

### Existing problem
- The backend was structured as monolithic route handlers directly calling Mongoose models, handling business rules, generating PDFs, and sending responses in single 100+ line callback functions.
- Passwords were being logged directly to standard out in registration handlers.
- `backend/routes/Receipt.js` had a capitalized file name that breaks on case-sensitive Linux serverless deployment environments.
- Lack of strongly-typed domain error classes led to inconsistent status codes and ad-hoc error formats.

### Implementation
1. **Domain Error Hierarchy (`backend/src/errors/AppError.js`):**
   - Implemented `AppError`, `BadRequestError` (400), `UnauthorizedError` (401), `ForbiddenError` (403), `NotFoundError` (404), and `ConflictError` (409) with operational error tagging.
2. **Business Services Layer (`backend/src/services/`):**
   - Created `authService.js`: Business logic for registration, authentication, JWT token issuance, and profile retrieval/updating. Removed all console password logging.
   - Created `flavourService.js`: Business logic for flavour retrieval, unique creation, reactivation of soft-deleted flavours, updates, and soft deletion.
   - Created `receiptService.js`: Business logic for receipt querying, single receipt retrieval, receipt persistence, and removal.
3. **HTTP Controllers Layer (`backend/src/controllers/`):**
   - Created `authController.js`, `flavourController.js`, and `receiptController.js` mapping HTTP requests to services with automated next-error delegation.
4. **Clean Route Layer (`backend/src/routes/`):**
   - Created `authRoutes.js`, `flavourRoutes.js`, `receiptRoutes.js`, and central `index.js`.
   - Fixed Linux case-sensitivity by providing lowercase `receipt.js` alongside backwards-compatible re-exports.
5. **Standardized Error Handling:**
   - Centralized error response formatting in `backend/server.js` separating 4xx operational failures from 5xx server errors, hiding stack traces outside development.
6. **Integration Tests (`backend/tests/architecture.test.js`):**
   - Added automated tests verifying `AppError` class status codes and operational tags.
   - Verified that routes mount properly under `/api/auth`, `/api/flavours`, and `/api/receipts` and reject unauthenticated requests with HTTP 401.

### Architecture impact
Separated concerns into Routes -> Controllers -> Services -> Models. Preserved full backwards compatibility with existing frontend endpoints while enabling isolated unit testing of business logic.
