# Pull Request 13: Product and Flavour Management Improvements

## Title
`feat(catalog): product categories, SKU, availability toggles, soft-delete archiving, and historical receipt price preservation`

## Overview
This PR improves product and flavour management for business retail workflows. It introduces categories, SKUs, in-stock/out-of-stock toggles, non-destructive archiving (soft delete), query filtering, and automated verification that product catalog price updates never alter previously issued historical receipts.

## Key Changes
1. **Flavour Model Enhancement (`backend/src/models/Flavour.js`)**:
   - Added `category` with a default of `'Fresh Juice'` and length bounds.
   - Added `sku` (automatically uppercased and trimmed).
   - Added `isAvailable` (boolean toggle for in-stock / out-of-stock items, default `true`).
   - Added `isArchived` (boolean flag for soft-delete archiving, default `false`).
   - Added compound indexes:
     - `{ userId: 1, category: 1 }`
     - `{ userId: 1, isArchived: 1, isAvailable: 1 }`

2. **Flavour Service Expansion (`backend/src/services/flavourService.js`)**:
   - `getAll(userId, query)`: Supports filtering by `category`, `isAvailable`, `search` (name, description, SKU), and excludes archived items by default.
   - `archive(userId, id)`: Soft deletes product while retaining it for historical reporting.
   - `restore(userId, id)`: Restores an archived flavour back into the active catalog.
   - `toggleAvailability(userId, id)`: Instantly toggles in-stock / out-of-stock state.
   - Preserves reactivity if creating a flavour with a previously archived name.

3. **Routes and Controller (`backend/src/routes/flavourRoutes.js` & `flavourController.js`)**:
   - Added `PATCH /api/flavours/:id/archive`
   - Added `PATCH /api/flavours/:id/restore`
   - Added `PATCH /api/flavours/:id/toggle-availability`

4. **Payload Validation (`backend/src/validators/flavourValidators.js`)**:
   - Validates `category`, `sku`, `isAvailable`, and `isArchived` fields with strict attribute checking.
