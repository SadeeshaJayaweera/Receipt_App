# Pull Request 34: End-to-End API Integration Testing Suite

## Title
`test(e2e): end-to-end API integration suite spanning user onboarding, catalogue, POS checkout, void audit, analytics, and session revocation`

## Overview
This PR introduces a comprehensive End-to-End (E2E) API integration testing suite (`backend/tests/e2eScenario.test.js`) validating the entire business workflow across all backend modules and middleware. The test suite exercises realistic operational flows in sequence, ensuring seamless interoperability between authentication, multi-tenant isolation, decimal financial calculations, receipt numbering, status history auditing, analytics aggregation, and token revocation.

## Key Changes
1. **End-to-End Workflow Scenario Testing (`backend/tests/e2eScenario.test.js`)**:
   - **Step 1: Security Perimeter Validation**:
     - Confirms unauthenticated requests without bearer tokens are strictly rejected with HTTP 401.
   - **Step 2: Store Profile & Branding Configuration**:
     - Tests `PUT /api/auth/profile` setting tenant custom receipt prefix (`CITRUS`), logo icon (`🍹`), and store tagline.
   - **Step 3: Product Catalogue Management**:
     - Tests `POST /api/flavours` creating menu items with categories, SKU (`AVO-01`), and stock availability.
     - Validates `GET /api/flavours` retrieves tenant-isolated catalogue.
   - **Step 4: POS Sale Transaction & Checkout**:
     - Executes `POST /api/receipts` with multiple line items, 10% discount, customer info, and cash tender.
     - Verifies sequential numbering format (`CITRUS-YYYYMM-0001`), decimal subtotal computation, and cash change calculation (`Rs. 560`).
   - **Step 5: Financial Immutability Protection**:
     - Validates that issued receipts reject financial mutations (quantity/price edits) with HTTP 400.
   - **Step 6: Receipt Voiding & Audit Trail**:
     - Tests `POST /api/receipts/:id/void` with mandatory explanation.
     - Verifies status transitions to `voided` and appends audit log entry to `statusHistory` recording user ID, timestamp, and reason.
   - **Step 7: Business Dashboard & Financial Analytics**:
     - Verifies `GET /api/analytics` returns aggregated revenue, top flavours, and payment breakdowns.
   - **Step 8: Session Logout & Token Revocation**:
     - Tests `POST /api/auth/logout` revoking current token `jti` in `tokenBlacklistService`.
     - Confirms subsequent API requests with the revoked token are immediately rejected with HTTP 401.
