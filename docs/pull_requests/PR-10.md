# Pull Request 10: Financial Data Integrity & Receipt Numbering

## Title
`feat(finance): implement atomic sequential receipt numbering and ReceiptCounter model`

## Overview
This PR resolves race conditions and financial integrity gaps in receipt numbering by introducing an atomic counter model (`ReceiptCounter`) and a dedicated generation service (`receiptNumberService`). It replaces non-atomic count queries with collision-safe, tenant-isolated sequential identifiers formatted as `RCP-YYYYMM-0001`.

## Key Changes
1. **`ReceiptCounter` Model (`backend/src/models/ReceiptCounter.js`)**:
   - Stores tenant sequence state partitioned by `userId`, `prefix` (default `RCP`), and `period` (`YYYYMM`).
   - Defined compound unique index `{ userId: 1, prefix: 1, period: 1 }` to guarantee that counter sequences cannot collide or duplicate.
   - Enforced validation rules on period format and non-negative sequence numbers.

2. **`ReceiptNumberService` (`backend/src/services/receiptNumberService.js`)**:
   - Implemented `generateNextReceiptNumber(userId, options)` utilizing atomic MongoDB `findOneAndUpdate` with `$inc: { seq: 1 }` and `upsert: true`.
   - Generates predictable, audit-compliant identifiers (e.g. `RCP-202611-0001`, `RCP-202611-0002`).
   - Supports configurable zero-padding (default 4 digits) and custom prefixes (`INV`, `RCP`).
   - Added `getCurrentSequence` for peeking without incrementing.

3. **Receipt Service Integration (`backend/src/services/receiptService.js`)**:
   - Integrated atomic receipt numbering directly into the receipt creation pipeline.
   - Preserves custom receipt numbers if explicitly passed from offline/cached clients.

4. **Schema Pre-Validate Fallback (`backend/src/models/Receipt.js`)**:
   - Replaced fragile `countDocuments` logic in `pre('validate')` with atomic generator delegation.

5. **Request Validation (`backend/src/validators/receiptValidators.js`)**:
   - Allowed optional client-supplied `receiptNumber` up to 50 characters while strictly validating all other fields.
