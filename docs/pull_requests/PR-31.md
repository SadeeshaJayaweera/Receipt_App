# Pull Request 31: Client State & Network Resilience

## Title
`feat(client): network resilience with exponential backoff retries, error normalization, and offline status banner`

## Overview
This PR hardens client-side network communications and state reliability. It enhances the Axios API client (`frontend/src/api/client.js`) with intelligent exponential backoff retry mechanisms for idempotent operations (GET, HEAD, OPTIONS) facing transient 502/503/504 gateway failures or connection timeouts. It introduces normalized error parsing (`extractErrorMessage`), seamless auth token lifecycle handling without aggressive reloads, and adds a global `NetworkStatusBanner` alerting cashiers to internet disconnections with manual connection checking.

## Key Changes
1. **Intelligent Exponential Backoff Retry Engine (`frontend/src/api/client.js`)**:
   - `isRetryableError`: Detects transient socket aborts (`ECONNABORTED`), network disconnects, and gateway outages (HTTP 502, 503, 504).
   - Automatically skips non-retryable 4xx client errors (400, 401, 403, 404, 422).
   - Retries idempotent GET/HEAD/OPTIONS operations up to 2 times with exponential backoff delays (`delay = BASE * 2^(retry-1)`).
2. **Centralized Error Normalization (`extractErrorMessage`)**:
   - Extracts structured server error messages (`response.data.message` or `response.data.error`).
   - Normalizes network timeouts and disconnection errors into friendly, actionable user messages.
3. **Global Network Status & Offline Awareness (`frontend/src/components/NetworkStatusBanner.jsx`)**:
   - Listens to window `online` and `offline` network transition events.
   - Fixed top banner warning cashiers when working offline.
   - Provides a "Check Connection" trigger for immediate network state re-verification.
   - Displays a confirmation banner when connection is restored.
   - Mounted in `frontend/src/App.jsx`.
