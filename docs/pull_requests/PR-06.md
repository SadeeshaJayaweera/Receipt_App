## PR-06: Authentication Hardening and Token Lifecycle Security

### Objective
Harden user authentication mechanisms by strengthening password hashing with bcrypt cost factor 12, introducing cryptographically unique token identifiers (`jti`), implementing server-side token revocation (`tokenBlacklistService`), providing a dedicated session invalidation endpoint (`POST /api/auth/logout`), and distinguishing expired vs revoked token states.

### Existing problem
- Passwords were saved using a lower bcrypt cost factor of 10.
- JWT tokens lacked unique token identifiers (`jti`), preventing granular token tracking or single-session revocation.
- There was no server-side logout or token revocation mechanism; tokens remained valid indefinitely until expiration even after users logged out on the client.
- Expired tokens were returned with generic 401 errors without clear differentiation from invalid signatures.

### Implementation
1. **Password Hashing Hardening:**
   - Upgraded `User.pre('save')` bcrypt cost factor to 12 rounds in `backend/src/models/User.js`.
2. **Cryptographic Token Identifiers (`jti`):**
   - Injected UUID-based `jti` into all signed JWT payloads in `authService.register` and `authService.login`.
3. **Server-Side Token Revocation (`backend/src/services/tokenBlacklistService.js`):**
   - Built in-memory token blacklist service tracking revoked tokens and expiration timestamps.
   - Configured unreferenced interval cleanup to prevent memory bloat.
4. **Logout Endpoint:**
   - Implemented `POST /api/auth/logout` route and controller handler in `authRoutes.js` and `authController.js` to immediately blacklist the user's active session token.
5. **Enhanced Authentication Middleware (`backend/middleware/auth.js`):**
   - Checks blacklist prior to cryptographic verification.
   - Specific user-facing messages for `TokenExpiredError` vs revoked tokens.
   - Attaches `req.token` and `req.tokenPayload` for downstream handlers.
6. **Automated Test Suite (`backend/tests/authHardening.test.js`):**
   - Verified valid JWT acceptance and `jti` extraction.
   - Tested rejection of expired tokens with descriptive error.
   - Tested rejection of blacklisted tokens.
   - Tested `POST /api/auth/logout` end-to-end revocation.
   - Verified bcrypt cost factor 12 hashing format.

### Files changed
- `backend/src/models/User.js`: Upgraded bcrypt salt rounds to 12.
- `backend/src/services/tokenBlacklistService.js`: Token blacklist and revocation manager.
- `backend/src/services/authService.js`: Added `jti` to JWT and implemented `logout()`.
- `backend/src/controllers/authController.js`: Added `logout()` handler.
- `backend/src/routes/authRoutes.js`: Exposed `POST /logout` route.
- `backend/middleware/auth.js`: Integrated blacklist checking and granular error responses.

- `backend/tests/authMiddleware.test.js`: Updated assertions for standardized error format.
- `docs/pull_requests/PR-06.md`: PR record.

### Architecture impact
Introduced stateful session revocation to stateless JWTs, providing immediate session termination upon user logout while preserving high verification performance.

### Testing

### Security considerations
Prevents replay of stolen or discarded JWTs post-logout. Enforces increased resistance against brute-force password cracking by increasing bcrypt work factor to 12.
