# Pull Request 11: Authoritative Decimal Calculation Engine

## Title
`feat(finance): implement authoritative decimal calculation engine for backend and frontend`

## Overview
This PR introduces a single authoritative financial calculation engine (`calcEngine.js`) to eliminate floating-point arithmetic errors (such as `0.1 + 0.2 = 0.30000000000000004`), standardize discount and tax computations, and ensure 100% mathematical parity across the backend API and frontend interfaces.

## Key Changes
1. **Financial Calculation Engine (`backend/src/utils/calcEngine.js` & `frontend/src/utils/calcEngine.js`)**:
   - Built exact half-up rounding (`round(value, decimals = 2)`).
   - Built integer minor units conversion (`toMinorUnits` and `fromMinorUnits`) preventing fractional cents accumulation.
   - Built `calculateLineItem` generating deterministic line-item subtotals.
   - Built `calculateReceiptTotals` managing:
     - Line-item sum in integer cents.
     - Fixed and percentage discounts, capped strictly at the subtotal to prevent negative balances.
     - Configurable tax handling (**tax off by default**; computed on taxable amount after discounts when enabled).
     - Authoritative final totals.
   - Built `calculateChange` computing cash overpayments, change due, and shortfalls.
   - Built `formatCurrency` with standardized `LKR` (`Rs. 1,250.00`) and `USD` (`$12.50`) formatting.

2. **Backend Service Integration (`backend/src/services/receiptService.js`)**:
   - Replaced naive client sum trust with server-authoritative calculations via `calculateReceiptTotals`.
   - Recomputes item subtotals, order subtotal, discounts, and taxes on receipt updates.

3. **Validation Synchronization (`backend/src/validators/receiptValidators.js`)**:
   - Added validation support for `discountType` (`'fixed'` | `'percent'`), `discountValue`, and `taxEnabled`.
