# Pull Request 18: Multi-Currency & Regional Formatting

## Title
`feat(currency): multi-currency isolation (LKR/USD), currency formatting, and business profile preferences`

## Overview
This PR hardens multi-currency isolation and regional formatting rules across both backend and frontend layers. It introduces standardized currency helpers, symbol lookup, currency assertions preventing accidental cross-currency calculations, and user profile configuration for business default currencies and tax preferences.

## Key Changes
1. **Authoritative Currency Engine (`backend/src/utils/calcEngine.js` & `frontend/src/utils/calcEngine.js`)**:
   - Added `SUPPORTED_CURRENCIES` set with `LKR` and `USD`.
   - Added `isValidCurrency(code)` validation helper.
   - Added `getCurrencySymbol(code)` mapping (`Rs.` for `LKR`, `$` for `USD`).
   - Added `assertSameCurrency(codeA, codeB)` guard throwing `ValidationError` if mismatched.
   - Extended `formatCurrency(amount, currency, options)` to support multiple display modes:
     - `symbol` (default): `Rs. 1,250.00`, `$25.50`
     - `code`: `1,250.00 LKR`, `25.50 USD`
     - `both`: `Rs. 1,250.00 LKR`, `$25.50 USD`
2. **Business Currency & Tax Settings (`backend/src/validators/authValidators.js` & `backend/src/services/authService.js`)**:
   - Added `defaultCurrency` (`LKR` or `USD`), `taxEnabled` (boolean, default `false`), `taxRate` (non-negative percentage), and `receiptFooter` (customizable footer message) to profile update validation schemas.
   - Updated `authService.getProfile()` and `authService.updateProfile()` to expose and update business currency and receipt settings.
3. **Mongoose Buffer Safe Initialization**:
   - Hardened `receiptService.js` to ensure clean handling of Mongoose connections across environments.
