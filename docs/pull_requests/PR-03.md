## PR-03: Environment and Configuration Management

### Objective
Centralize and strictly validate application environment configuration using Zod schemas, enforcing safe defaults for local/test environments and fail-safe startup validation for production environments to prevent runtime crashes and secret leaks.

### Existing problem
- Environment variables were read ad-hoc via `process.env` scattered across route files, middleware, and entry points with inconsistent fallback logic.
- No schema validation existed, meaning missing critical variables like `MONGODB_URI` or `JWT_SECRET` resulted in runtime crashes or undefined behavior.
- Insecure defaults and lack of type coercion (e.g. `PORT` strings vs numbers).

### Implementation
1. **Centralized Configuration Module (`backend/src/config/env.js`):**
   - Implemented Zod-validated `envSchema` covering `NODE_ENV`, `PORT`, `MONGODB_URI`, `JWT_SECRET`, `JWT_EXPIRES_IN`, `FRONTEND_URL`, `RATE_LIMIT_WINDOW_MS`, and `RATE_LIMIT_MAX`.
   - Built `loadConfig()` function supporting runtime overrides, test-environment fallbacks, and fail-fast production error reporting.
2. **Server & Middleware Integration:**
   - Updated `backend/server.js` to consume typed `config` object instead of raw `process.env`.
   - Updated `backend/middleware/auth.js` and `backend/routes/auth.js` to consume `config.JWT_SECRET` and `config.JWT_EXPIRES_IN`.
3. **Automated Validation Testing (`backend/tests/envConfig.test.js`):**
   - Created test suite verifying valid environment parsing and port coercion.
   - Tested safe failure when `MONGODB_URI` or `JWT_SECRET` is missing or insufficient in production.
   - Verified automated fallbacks in test environments.

### Files changed
- `backend/src/config/env.js`: Centralized schema and loader.
- `backend/server.js`: Integrated centralized configuration.
- `backend/middleware/auth.js`: Integrated configuration for JWT verification.
- `backend/routes/auth.js`: Integrated configuration for JWT issuance.
- `backend/tests/envConfig.test.js`: Added 4 automated configuration test cases.
- `docs/pull_requests/PR-03.md`: PR record.

### Architecture impact
Replaced scattered raw `process.env` calls with an immutable, validated configuration object ensuring consistency and fail-fast startup behavior.

### Testing
- `backend/tests/envConfig.test.js`: 4/4 passing tests.
- Full backend suite: 8/8 passing tests across 3 suites.
- Full root test suite: 100% passing tests.

### Security considerations
Ensures `JWT_SECRET` cannot be empty or trivially short in production, and prevents server startup if database connection parameters are missing.
