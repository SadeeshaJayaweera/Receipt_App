# Pull Request 36: Containerization & Docker Setup

## Title
`infra(docker): containerize multi-stage backend, frontend with nginx, and multi-service docker-compose orchestration`

## Overview
This PR introduces production-grade, reproducible containerization configurations across the entire application stack. It provides multi-stage Dockerfiles for both backend and frontend, an Nginx reverse proxy configuration with client-side SPA routing and security headers, persistent volume configurations, healthcheck definitions, non-root user enforcement, and a comprehensive `docker-compose.yml` for unified local and production orchestration.

## Key Changes
1. **Backend Containerization (`backend/Dockerfile`, `backend/.dockerignore`)**:
   - **Multi-Stage Build**: Separates dependency installation (`node:20-alpine AS dependencies`) with `npm ci --omit=dev` from the runtime image (`AS runner`).
   - **Least Privilege Security**: Enforces unprivileged `USER node` execution, preventing container root privilege escalation.
   - **Healthcheck Probe**: Probes `GET /api/health/live` with interval, timeout, and retry parameters.
   - **Environment Control**: Sets `NODE_ENV=production` and exposes standard port `5001`.

2. **Frontend Containerization (`frontend/Dockerfile`, `frontend/nginx.conf`, `frontend/.dockerignore`)**:
   - **Multi-Stage Build**: Compiles React SPA artifacts via Node 20 (`AS builder`), copying production static assets into a lightweight `nginx:1.27-alpine` runner.
   - **SPA Routing Fallback**: Configures Nginx with `try_files $uri $uri/ /index.html;` to ensure deep-link routing works seamlessly.
   - **Internal Reverse Proxy**: Proxies `/api/` traffic directly to `http://backend:5001/api/`.
   - **Performance & Security**: Implements Gzip asset compression and standard security response headers (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`).
   - **Container Healthcheck**: Probes `/health` endpoint returning HTTP 200.

3. **Multi-Container Stack Orchestration (`docker-compose.yml`, `.dockerignore`)**:
   - **Services**:
     - `mongodb`: MongoDB 7.0 database engine with persistent named volume `mongo_data` and active `db.adminCommand('ping')` healthcheck.
     - `backend`: Node.js Express API service depending on healthy `mongodb`.
     - `frontend`: Nginx web server mapped to port `3000:80` depending on healthy `backend`.
   - **Isolated Network**: Bridges all services inside a dedicated `receipt-net` bridge network.

4. **Automated Manifest Verification (`backend/tests/dockerConfig.test.js`)**:
   - Unit tests validating syntax, non-root execution, healthcheck commands, port mappings, and `.dockerignore` filters.
